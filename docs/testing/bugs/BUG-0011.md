# BUG-0011: `aad-cli run --save` does not write `<file>.aadrev.json`

Severity: S2     Status: open     Found: 2026-11-01 by agent in run 2026-11-01-o-draft
App and version: installed `aad-cli 0.6.0` (`%LOCALAPPDATA%\Programs\O-Draft\aad-cli.exe`); MynaCAD commit `a427438`
Test case: DRF-FIL-03
Area: D2 Files

## Steps to reproduce
1. `aad-cli run --sample --save C:\Temp\odraft-testrun-2026-11-01\rev2.dxf`
2. Look for `rev2.dxf.aadrev.json` beside the file.
3. `aad-cli run rev2.dxf --cmd "drawing.revision {}"`

## Expected
Every DXF/DWG save writes `<file>.aadrev.json` (SHA-256, bytes, time, entity count). `drawing.revision` reports `status: current` (or at least `recorded` present). Docs: `docs/status.md` Drawing revision row.

## Actual
- No `.aadrev.json` beside the CLI-saved file.
- `drawing.revision` returns `"status":"unrecorded","recorded":null` with a sha256 of the file on disk.
- Contrast: WinUI control `app.save` to `host-save.dxf` **does** write `host-save.dxf.aadrev.json` (184 bytes).

- **Fix:** `aad-cli run --save` / `--save` writes bytes via `export_framed` and never calls `revision::record`. Overwriting an existing path also skips the `.bak` backup that engine `save`/`saveas` creates (`cmd/file.rs` `store`).

## Evidence
- evidence/2026-11-01-o-draft/BUG-0010/ (host sidecar present; notes)
- `C:\Temp\odraft-testrun-2026-11-01\rev2.dxf` with no sidecar
- `C:\Temp\odraft-testrun-2026-11-01\host-save.dxf.aadrev.json`

## Notes
Workaround: save through the WinUI shell / `engine.execute` `save`, not `aad-cli --save`.
