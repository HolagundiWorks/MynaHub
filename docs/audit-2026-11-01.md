## WCAG Findings

### S1 · FIXED — Window border contrast (WCAG 1.4.11 Non-text Contrast)

**File:** `native/Adms.Desktop/AppTheme.cs`  
**Criterion:** 1.4.11 Non-text Contrast (AA) — minimum 3:1 for UI component boundaries  
**Was:** `ColorRef(138, 147, 163)` → #8A93A3 against title-bar background #E4EAF2 → **2.56:1 — FAIL**  
**Now:** `ColorRef(112, 120, 135)` → #707887 against #E4EAF2 → **3.67:1 — PASS**  
**Dark border** `ColorRef(120, 120, 120)` → #787878 against #1B1B1B → 3.90:1 — was already passing, unchanged.

Note: the `tools/a11y/contrast.mjs` tool does not test DWM border/title-bar colours defined in `AppTheme.cs`.
These values are set programmatically and fall under author control per WCAG § 1.4.11.
**Recommendation:** add the six DWM colours (light + dark × caption bg / foreground / border) as a checked pair group in `contrast.mjs`.

## Code Quality Fixes

### C1 · FIXED — Infallible `.unwrap()` → `.expect()` (`office-core/src/clients.rs`)

`blank_brief()` constructs and returns `Value::Object(body)`. The `.as_object_mut()` call on its
return value cannot fail. Two callsites used silent `.unwrap()`; changed to `.expect()` with an
invariant comment so future readers know the panic is impossible rather than assumed safe:

```rust
// clean_brief(), line ~443
let stored = body.as_object_mut().expect("blank_brief always returns Object");

// get_brief(), line ~471
let fields = body.as_object_mut().expect("blank_brief always returns Object");
```
