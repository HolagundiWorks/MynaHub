# Private project attachments

Implemented 2026-11-17 for the company API and Mobile. Files are stored in a private Neon Object Storage bucket on the same branch as their metadata. Mobile receives no Neon database or storage credentials, object keys or signed storage URLs. Its uploads/downloads go through the company API with current project authorization.

Supported formats are PDF, PNG, JPEG, WebP, UTF-8 TXT and CSV, up to 5 MiB. Names, extensions, base64 encoding, size and format signatures are checked. File IDs and operation IDs are stable UUIDs. Content is immutable after upload; replacing a document means a new file. Metadata contains name, content type, byte count, SHA-256 and revision. Downloaded bytes must match metadata size/hash in the API and again in Mobile.

GET /v1/files/status reports private-storage availability and supported limits. GET/POST /v1/projects/:projectId/files lists/uploads; GET /v1/projects/:projectId/files/:id/content returns verified bytes in a bounded base64 envelope. DELETE /v1/projects/:projectId/files/:id requires the expected revision, literal DELETE confirmation and a fresh login. Deletion hides metadata/content from live access and retains the private object, tombstone, operation receipts and audit history; it is not permanent erasure.

Reads require current project read scope. files.write permits uploads and files.delete permits removal, each within its own role scope. Owner, Administrator, Principal and Project Manager receive both by default. Document editor and Site Supervisor receive upload permission within assigned-project scope. Custom file permissions require projects.read. Foreign, missing or revoked project/file IDs do not disclose file content.

The live poll accepts fileProjectId/fileAfter for an independently paginated filePage of at most 25 records on a currently visible project. Uploads/deletions use immutable actor/company receipts and recheck current authority before replay. A tombstoned upload cannot be replayed into an active file. Raw runtime metadata/identity writes are denied. Controlled functions construct storage keys from authoritative company/project/file IDs and content hashes. UUID case is canonicalized for object paths and locks.

Private ACLs are checked before object access; public ACL grants are refused. Object reads use a bounded range and close oversized/error streams. Transfers are bounded by payload size, per-route rate limits, and per-user/global concurrency. Successful registration, receipt and audit are transactional. Failed registration cleans up its own new object while holding the per-file lock. A process crash or storage outage can leave a private, unreferenced object: retention/reconciliation policy is still a production rollout task. Stored business objects are not purged by build/temp cleanup.

## Mobile memory-only workflow

Choose a local file, then select its company project and explicitly confirm upload. The picker retains no target project while backgrounded and no persistent URI permission or source copy is taken. Results restored after process recreation are ignored. Upload selections, drafts, confirmations, file metadata and previews remain in RAM and clear on backgrounding, leaving, disconnecting or lost scope. Late network completions cannot restore company state after leaving. No download/export-to-disk feature, offline file cache or backup is added.

PDF/image parsing runs in a nonexported isolated Android service without app permissions, credentials, app files or network access. A seekable RAM-backed proxy descriptor supplies input; only bounded raw pixels return through IPC. PDF previews support at most 500 pages; preview images are at most 1400 pixels per dimension. Requests time out and the isolated process ends when unbound. TXT/CSV previews are bounded to 50,000 characters and 1,000 lines. Preview windows prevent screenshots/recent-task capture. The main API/file transport is bounded to 8 MiB; the generic transport keeps its 1 MiB default.

See Android's [proxy descriptor API](https://developer.android.com/reference/android/os/storage/StorageManager#openProxyFileDescriptor(int,android.os.ProxyFileDescriptorCallback,android.os.Handler)) and [PDF renderer isolation guidance](https://developer.android.com/reference/android/graphics/pdf/PdfRenderer), and Neon's [S3 compatibility](https://neon.com/docs/storage/s3-compatibility) and [storage credential model](https://neon.com/docs/storage/authentication).

## Configuration and verification

Storage is optional until configured. Set ATTACHMENTS_BUCKET plus AWS_ENDPOINT_URL_S3, AWS_REGION, AWS_ACCESS_KEY_ID and AWS_SECRET_ACCESS_KEY on the API host, using the intended branch's private bucket and scoped credentials. No secrets belong in git, APKs, source assets or logs. The connected MynaHub project is soft-cherry-88367368; preview/demo were explicitly targeted. Production and real-owner development were not migrated.
